# Windows 快速安装验证记录

本轮仅修改安装入口、部署编排、诊断及文档。现有机器人、Sites、业务库及两套Excel生成器不在修改范围。

隔离安装和模拟云端测试不等同于全新Windows电脑及新Telegram/Cloudflare账户真实部署。

## 已执行的本机隔离检查

- 在独立新目录实际运行PowerShell统一安装入口的离线业务阶段：复制白名单源码、创建新虚拟环境、安装全部锁定Python依赖、pip check、npm ci、初始化空白主库/进度库，均成功。无模拟员工登记，无polling启动。再次运行已安装目录入口同样成功。
- 另一个独立目录实际安装锁定Wrangler 4.151.0，构建Worker并完成 `wrangler deploy --dry-run`；未上传Worker，未登录或读取原公司Cloudflare账户。使用现有电脑已有解释器/Node，通过独立测试适配器提供npm；不等同于干净电脑从零安装系统运行环境。
- 统一诊断实际检查隔离目录：有效业务员0、本目录polling实例0；电脑原运行实例1棵进程树；未部署的云端、BotFather及未验证话题明确显示待处理，没有假报成功。
- 已有Python完整业务回归运行通过，退役界面明确跳过。最终同树回归、前端/Worker JS与迁移门禁由 `sync-github.cmd` 再执行，准确命令、结果及树版本保留在Git提交的 Validation-Checks 中。

## 安装专项自动化

`python -m unittest discover -s tests -p test_company_setup.py -v`，15项专项用例，验证：

| 范围 | 验证方式 |
| --- | --- |
| 全新目录、完整源码/模板 | 实际复制允许清单，拒绝原项目及重叠目录，不复制.env/数据/Git |
| 复制中断继续、配置保留 | 删除一个已复制源码再补齐；本地源码变更拒绝覆盖 |
| 独立密钥、空库 | 两公司随机密钥不同，初始化无员工/任务，重复初始化保留已存在记录 |
| 错误配置 | 拒绝非法Token格式、错误数字身份/话题、跨目录数据路径及正式模式 |
| Python/Node缺失 | Windows PowerShell 5.1实际解析，并对真实检测函数模拟缺少命令；未在本机卸载环境或执行winget安装 |
| 云授权 | 模拟已有授权复用、首次浏览器登录、单账户自动选择、多账户选择与账户错配拒绝 |
| 云部署失败/恢复 | 模拟上传中断，恢复不重复创建D1；SQL重复初始化不丢原行 |
| 密钥保护 | 桥接密钥仅通过stdin；状态、前端配置及命令行无Token/桥接密钥；bootstrap关闭 |
| Telegram权限/路由 | 模拟Bot ID错误、成员无权限、网络失败和机器人被误填为所有者；两个话题部分失败后只补未成功部分，不取getUpdates |
| Mini App绑定 | 验证独立t.me短名入口，拒绝非法短名；后台诊断分别检查HTTPS、认证、D1、心跳，不混为一次健康检查 |
| 单实例 | 实际安装锁及既有运行实例锁的冲突测试；诊断模拟多实例拒绝 |
| 故障脱敏 | 外部命令失败隐藏原始输出，不打印凭据，给出失败步骤及重试方法 |

## 未真实验证及人工授权边界

没有接入真正全新的Windows电脑、新公司的Telegram机器人/工作群或新Cloudflare账户。因此未验证：winget在新电脑实际安装/UAC、本人Cloudflare授权及真实资源创建、workers.dev启用、真实BotFather短名、两个真实话题路由、本人客户端签名打开与业务提交、新电脑重启后的登录自启、该网络下断线恢复。

这些项目需要部署公司的合法账号/本人浏览器授权与首次正常使用，不能拿原公司Token、数据库、员工或Sites作为替代测试。安装器无法自动证明另一台电脑未运行同Token，启动前由该公司确认。不同公司仍需分别管理套餐、额度及费用。

本轮未改变原业务源码、Excel生成器、模板、群配置、现有Sites和运行实例；正式调度保持关闭。后续升级、真实启用及任何线上发布需遵守原授权边界。
