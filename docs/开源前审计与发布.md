# 开源前审计与发布

此文档是长期复核流程。用户已于2026-10-15授权本仓库公开并采用MIT；已核实的非密钥公开标识和本机路径按用户决定保留，历史未重写。此授权不豁免未来的秘密或业务数据检查。

## 必须覆盖的范围

1. 确认 origin、GitHub 当前私有性及账号权限，拉取全部可见分支和标签，比较 `git ls-remote`。列出历史提交与本地未引用对象；检查提交/标签信息、文件路径、二进制内容、LFS/子模块及作者邮箱。
2. 在仓库外运行 `python scripts/publication_audit.py --output ../private-audit/git-history.json`。该工具只读所有本地 Git 对象，保留位置与规则，不输出匹配值；退出码1表示仍需处理。它不会访问或清除 GitHub 服务器缓存，也不代替远程附件核查。
3. 使用授权的 GitHub API 逐页核查所有分支、标签、Release/附件、Actions 运行/日志/工件/缓存、PR/Issue 附件、部署与环境。API 不可用须标为未确认，不能当成零风险。不要导出任何 Secret 实值。
4. 对 `.env` 已知秘密、公司群/机器人标识及只读人员资料进行比对；再人工检查前端、脚本、通用模板、测试样例和高熵常量。实际业务库、Excel、日志、备份、截图、训练正文不属于公开源码。
5. 两个格式模板必须检查内部文件、隐藏内容、关系、外部链接、批注、宏/嵌入及元数据，确认仅为格式/模拟值。不得通过删除真实业务数据来“做成模板”。
6. 验证源码清单具备 Mini App、云端 Worker/D1、Windows 工具、锁定依赖、初始化/恢复工具与测试。从干净源码副本检查部署文件，不复制当前公司的配置或数据。
7. 复核新电脑钩子、暂存/推送扫描、失败保留本地提交及拒绝强推；测试使用独立临时仓库，不连接实际员工账户。

## 发布门槛

发现真实凭据或个人/业务数据时不得公开。由所有者安排轮换、历史处理与缓存清理；提交删除文件不足以移除历史。只读审计工具不会执行这些破坏性操作。

即使是公开的公司机器人标识、工作路径等非密钥信息，也需明确记录并由所有者决定是否保留；不得把它们描述为员工账号或密钥泄露。若决定严格移除，需要另行授权历史重写、协调克隆者与重新核验，不得沿用禁止强推的常规同步权限擅自操作。

同步工具使用精确仓库授权和allow_public显式授权，并核实当前账户的推送权限。公开切换已获用户授权；今后更改远端、可见性或放宽保密规则仍需单独审查。不能为了上传而取消扫描、测试凭证及历史冲突保护。

GitHub 变更可见性会影响可下载的历史及 Actions 信息，参见 [官方可见性说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)。后续 Release 只能从审核过的源码生成，不复制本机整个工作目录。

## 长期维护

每个 PR/提交检查代码、模板和打包清单，安装钩子，运行相关测试及同步脚本。依赖更新另外验证，不把安全审计变成线上自动部署；不自动重启机器人、启用调度或切换运营。完整审计原始证据放在私有外部目录，公开报告只能使用脱敏摘要。
