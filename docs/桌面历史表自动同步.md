# 桌面历史表自动同步

本功能只复制已经生成成功的 Excel，不改变数据库、提交规则、原导出入口或格式。`exports` 原文件保留，桌面修改不会写回数据库。日报与进度仍分别使用自己的数据源和固定文件名。

## 配置

通用部署包默认关闭。在本公司的本地 `.env` 设置 `DESKTOP_HISTORY_DIR`，重启当前实例生效。Windows 可配置 `DESKTOP_HISTORY_DIR="desktop:工作历史记录表"`，通过系统 API 取得实际桌面路径，兼容桌面重定向；也可填写本公司已有目录的绝对路径。目录必须事先存在，程序不会在其他位置创建同名文件夹。不要把本公司的实值路径带入其他公司的配置。

固定副本为 `日报历史记录.xlsx` 和 `工作进度历史.xlsx`。前者保留每日汇总、员工明细两张表，后者保留查询汇总、员工进度历史、当前问题历史、任务定义四张 V2 表。

## 更新与恢复

日报保存或修改、进度查询或反馈成功后，由原导出流程生成最新版本。独立同步循环每两秒检查一次导出完成状态，原文件更新完成后再复制；不会复制仍待生成的旧版本，不阻塞业务保存、Telegram 回执或小程序接口。原导出生成耗时仍取决于数据量及文件占用情况。

复制前校验 XLSX ZIP 和工作表结构，用同目录临时文件写入、刷新到磁盘并原子替换固定副本。WPS/Excel 占用或目录暂时不可用时保留旧有效副本，记录待同步，下次自动重试，不关闭任何用户程序。两份文件分别重试，一份失败不阻塞另一份。

机器人每次启动重新核验原文件和桌面副本的 SHA256，缺失或不同则补齐。同步状态在当前运行数据目录的 `desktop-sync-state.json`，包含状态、版本、路径、校验值及错误类型；不包含员工内容。`已同步` 表示本地副本一致，不能代表 OneDrive 已完成云端上传。

电脑关闭、休眠或机器人停止时同步也停止。文件释放后须保持机器人运行才能自动补写。若同步目录属于 OneDrive，仍由 OneDrive 管理上传，本功能不更改其设置。

## 验证边界

本次桌面真实文件复制、完整性检查、WPS 打开及现有实例重启后的同步状态已验证。隔离测试经过原日报处理入口和小程序查询/反馈入口，验证更新后同步及两份文件互不覆盖。Windows 实际文件共享锁验证了占用保留与释放重试；另外实际用本机 WPS 打开独立模拟工作簿，同步遇到 PermissionError 时保留旧文件，正常关闭该模拟工作簿后重试成功。没有向真实员工写入模拟日报或进度，也没有让员工重新提交；其他 WPS 版本及 OneDrive 云端上传未实测。

针对性测试：`python -m unittest discover -s tests -p test_desktop_sync.py`。使用独立临时目录和模拟身份，不读取真实培训正文，不启动第二个 polling。
