# Windows 新公司快速安装

## 准备

下载完整 GitHub 源码 ZIP 并解压。普通使用者无需 Git、GitHub 登录、Codex 或 ChatGPT。准备可持续开机的 Windows 电脑、可访问 Telegram/Cloudflare/Python 包仓库/npm 的网络、本人 Telegram 和 Cloudflare 账户。安装不购买资源；Cloudflare 套餐、额度及产生的费用由公司自行确认，不保证免费无上限。

在 BotFather 创建自己的机器人，保存 Token。创建启用话题的超级群，建立“每日报表”和“工作进度”。把机器人加入群，赋予管理员、邀请用户和置顶权限（不要求删除用户/提升管理员），关闭 BotFather `/setprivacy`。权限变更按 Telegram 提示重新加入群。员工保持普通群成员，群管理员不会自动获得程序业务管理员身份。

五项必填：Bot Token、明确的所有者数字 user_id、工作群数字 ID、日报话题 ID、进度话题 ID。可在 Telegram Web/公开话题链接中核对群/话题的数字；`https://t.me/c/数字群段/话题数字/...` 中群数字段需按 Telegram 超级群规则加 `-100`，不要把消息 ID 当话题 ID。本人数字 user_id 从可信账号资料/Telegram 数据导出取得，不能填用户名或依赖首次访问自动授予权限。机器人不能在安装前私聊获取未联系过它的用户身份。安装器会通过官方 API 检查配置对应的真实账号和成员关系，不按显示名猜测。

## 一个入口

双击 `setup-company.cmd`。默认运行目录是 Windows 当前用户 LocalAppData 内的 `TelegramTeamBot/company`，也可选独立新目录。下载目录与运行目录不能互相包含；目标若非空且不是本安装器所有，会拒绝操作。不要选择另一家公司的项目目录。

需要 Python 3.12+、Node.js 22+。缺少时可选择通过 winget 官方软件包安装；没有 winget 时给出 Python/Node 官方地址。Windows 安装器、UAC 或组织策略必须本人确认，不能绕过。依赖安装使用 requirements.lock.txt 与 deploy/package-lock.json，不安装 Codex 专用运行环境或制表工具；Excel 使用既有 openpyxl 兼容实现。机器存在代理时先配置适用于 pip/npm/Telegram/Cloudflare 的网络，不要把代理密码放进公开脚本。

安装器只复制公开白名单中的源码、模板和工具；不复制下载目录中的 `.env`、数据库、日志、备份、导出或 Git 凭据。生成 `.env` 和随机独立桥接密钥，默认 trial、正式调度关闭、AI 关闭、培训目录模式、桌面同步关闭。初始化空白主库和独立进度库，不导入模板模拟员工或旧公司的数据。原有编号兼容结构不代表创建了真实员工。

## 本公司 Cloudflare 和 Mini App

安装器先检查锁定版本 Wrangler 的已有授权；有效时复用，缺少时打开浏览器由本人登录自己的 Cloudflare。一个账户时自动选择，多个时只需选择本公司账户；中断恢复只允许原来绑定的账户。安装器以随机安装标识命名新的 Worker/D1，不绑定已有的任意名称数据库；中断后复用同一次安装的资源。云端 SQL 初始化可重复执行，不清空既有中转任务。Bot Token 只留在本地，Worker 仅获得 Bot 数字 ID；桥接密钥通过 secret put 标准输入传递。BOOTSTRAP_ALLOWED 始终 false，不调用 `/bridge/bootstrap`。

Worker 同时提供 Mini App 静态页面和D1中转，Windows 保持原有本地业务后台和 WebSocket/HTTP 兼容桥接架构。这里只为新公司部署其账户中的资源，**不迁移或更新原系统的 Sites**。账户若未启用 workers.dev，先在本公司 Cloudflare 控制台启用再继续；失败状态保留，不自动购买付费资源。

获得固定 HTTPS 后，必须本人在 BotFather `/newapp` 选择该机器人，填写名称、简介、图标、HTTPS 地址及短名。安装器保存 `https://t.me/机器人用户名/短名` 直接链接，群入口继续由现有机器人提供；不误用群内仅限私聊的 web_app 按钮。BotFather 操作不能由普通 Bot API 代办。输入短名只表示本人完成配置，安装器无法证明 Telegram 客户端实际正确打开，必须集中验收实际入口。

可同意向两个指定话题各发送一条“安装验收，不计正式数据”路由消息；API 回执核对群和话题 ID，不创建业务记录。未允许/回执不匹配即显示待处理，不宣称话题已经验证。部分话题成功后重试只补另一个。不会删除原消息，不通过 getUpdates 抢取现有实例的更新。

## 启动、检查和恢复

确认同 Token 未在其他电脑运行后，输入 START 才启动本公司的验收实例。安装器复用原 start.ps1/实例锁；已启动时不重复启动。同一个 Windows 目录只允许一个安装流程；运行实例的GUI解释器父子链算一棵进程树。不能仅凭本机进程证明远端电脑没有运行同 Token。

可选择安装当前用户登录自启动，任务名按运行目录计算，不覆盖其他公司的任务。后台使用原 pythonw 无控制台启动、监控和联网恢复机制。`stop.cmd` 安全停止本公司的进程树并写暂停标记，`start.cmd` 恢复。自启动安装不等于已经验证重启登录；需要在自己的新电脑集中验收。电脑关机/休眠或用户未登录时本地业务服务停用，网页仍可能可访问，不能保存反馈。

运行 `check-company.cmd`（只在安装器生成的公司目录有效）。检查结果逐项为通过、失败、待处理。联网检查使用 getMe/getChat/getChatMember/getWebhookInfo，不发送业务消息，不改变群权限，不清除Webhook。Webhook存在时阻止polling安装，先核实旧服务；不得在使用中的机器人上直接切换。Worker /health通过仅表示HTTPS可达，另检查桥接密钥与D1心跳，初次启动前显示桥接离线属于正常但尚待启动验证。员工人数来自实际批准/在职普通员工；空库为0，不填充30个模拟账号。业务管理员以明确所有者数字ID及原权限系统为准。

失败后重新运行**同版本下载包**并选同一目录，或在已安装目录重新运行 `setup-company.cmd`。pip/npm 可重试；配置、密钥和业务库不重置。云部署失败保留账户/资源标识，不同账户会被拒绝，防止误覆盖；账号登录可继续，本人授权不会自动绕过。配置值输错时在本公司 `.env` 内修正并重跑；Token不在终端显示，诊断不输出原始外部错误或凭据。不要删除 `.company-install.json` 来强制重新初始化。它是安装断点，不含Token和桥接密钥，仍应随本公司配置私密备份。

已完成部署后正常重跑复用既有云服务，不自动重新部署。需要重试本次未完成的云部署时安装入口会继续；需维护已部署本公司云服务可在本公司目录运行 `.venv\Scripts\python.exe scripts\company_setup.py cloud`，先检查Git版本与备份，不能对其他公司的服务操作。

## 升级及备份

本入口是首次安装与同版本中断恢复工具，不会静默覆盖本地改动。源码版本变化会停止并提示按既有升级/回退文档操作。升级前备份本公司配置、主库、进度库、审计及历史；更新仅源码，数据库兼容迁移沿用已有机制；不得用源码ZIP覆盖 data/exports，不把验收记录转成正式数据。详见[部署与恢复](独立公司部署与恢复.md)、[迁移工具](迁移工具说明.md)。

安装下载包不包含私有公司资料。公司的 `.env`、D1/Cloudflare授权、业务库、员工信息、导出Excel及备份单独私密保管，禁止上传到公开仓库。正式切换、工作日及调度启用需要公司所有者另行确认，安装器不会自动开启。

## 集中验收

一次检查：两话题路由、所有者/普通员工权限、员工首次正常“开始”、发送即提交日报及正确Excel、Mini App 发布/查询/本人反馈/总表/历史、断网恢复、文件占用重试、stop/start和Windows重新登录自启。程序测试与真实新电脑、新账号及BotFather客户端验收分别记录；未做的不能写通过。

命令依据：[Cloudflare Wrangler/D1](https://developers.cloudflare.com/d1/wrangler-commands/)、[Wrangler部署](https://developers.cloudflare.com/workers/wrangler/commands/workers/)、[Telegram Bot API](https://core.telegram.org/bots/api)、[Mini Apps](https://core.telegram.org/bots/webapps)。固定Wrangler依赖版本；将来升级CLI应重新验证部署参数。

启动成功与桥接就绪分开判断：安装器最多等待90秒；进程正常而云端尚未就绪会提示待处理，运行check-company.cmd复查，不重复安装。重新运行复用运行中的唯一实例。人工停止后双击start.cmd恢复；直接start.ps1需-Resume，监控不能解除人工暂停。旧实例升级必须先阅读[复核收尾与受控顺序](第三阶段关键修复.md#第三阶段复核收尾2026-10-18)，本工具不会默认强停旧进程。
