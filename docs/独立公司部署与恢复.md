# 独立公司部署与恢复
本包是完整源码，不依赖当前公司的 Token、群、数据库、域名或 Codex 账户。每家公司用独立目录、自己的 Bot Token/所有者数字ID/员工群/两个话题/数据库/HTTPS 服务及中转秘密。没有自动共享员工或业务记录。不得复制本公司的业务库及实值.env给另一公司。

## Windows 本地服务
1. 安装 Python 3.12+；解压独立目录，运行 install.cmd。锁定 Python 依赖包括 Telegram SDK、WebSocket、openpyxl。Excel无需必须拥有 artifact-tool；有时继续原生成器，无时兼容生成器。
2. 复制.env.example，运行configure.cmd填写自己的凭据、BOT_USERNAME、OWNER_USER_ID、ALLOWED_CHAT_ID、两个实际话题ID。RUN_MODE=trial，DATA_DIR和BACKUP_DIR使用本公司独立目录；AI_ENABLED=false，SCHEDULE_ENABLED=false。不需要 Gemini。
3. 初始化：.venv\Scripts\python.exe -m team_bot paths 校验配置；.venv\Scripts\python.exe scripts\migrate-progress.py 创建/兼容迁移自己的库，不导入模板模拟值。旧库迁移前停止并备份。不会新建虚假员工。
4. 运行test.cmd、start.cmd、diagnose.cmd。停用用stop.cmd。只运行一个polling，不使用别的getUpdates。登录后自启用autostart-install.cmd，网络断开后台自动重连；停止标记可防守护重启。

## 固定 HTTPS 中转部署
随包 deploy/worker.js、build-worker.mjs、0000_miniapp_bridge.sql、wrangler.toml.example 都是通用源码。可使用公司自己的 Cloudflare Worker/D1 固定 workers.dev 或自有域名，不以临时隧道冒充长期服务；是否有费用由账户实际资源决定，不自动购买。

安装 Node.js 20+及账户允许的 Wrangler。复制wrangler.toml.example为wrangler.toml，填自己的D1 ID及机器人数字ID；在deploy目录执行 node build-worker.mjs（构建器从项目miniapp目录打包）。创建独立D1并按0000_miniapp_bridge.sql执行结构初始化，再部署Worker。使用 wrangler secret put PROGRESS_BRIDGE_SECRET 设置随机强秘密，与本地.env一致，秘密不写源文件。BOOTSTRAP_ALLOWED=false，不开放初始化取密钥接口。需要自己的账户登录授权，包不包含任何现有账户凭据。

示例顺序（在deploy目录，使用自己的名字和授权账户）：
```
npx wrangler login
npx wrangler d1 create company-progress-relay
npx wrangler d1 execute company-progress-relay --remote --file=0000_miniapp_bridge.sql
node build-worker.mjs
npx wrangler secret put PROGRESS_BRIDGE_SECRET
npx wrangler deploy
```
自己的域名、D1及数字Bot ID必须填入配置，不照抄当前公司的值。机器人Token仅本地后台，云端存短期签名任务，过期清理；员工业务原始记录仍在本公司的库。

BotFather为自己的机器人配置Mini App固定HTTPS URL和short_name；群按钮链接为自己的 t.me/BOT/SHORT_NAME?startapp=...。本地设置PROGRESS_MINIAPP_ORIGIN、PROGRESS_MINIAPP_LINK、PROGRESS_MINIAPP_ENABLED=true、PROGRESS_MINIAPP_BRIDGE=true及中转秘密，FINAL_VERIFY_ENABLED默认false。后台验Telegram initData签名、时效、数字身份、实时成员及业务权限。公开页面不等于公开数据。

群中仅实际需要权限：发送、机器人自有消息编辑、必要置顶、成员核验；成员事件需要机器人为管理员，申请加入链接另需邀请权限。关闭BotFather群隐私后按平台要求重新添加。核实实际群与话题数字ID，不按显示名称判断。管理群保持人工沟通。

## 数据、备份与回退
每公司主身份/日报库为DATA_DIR/team.sqlite3，试用进度为progress-acceptance.sqlite3，正式进度为progress.sqlite3。数据、导出、备份不共享。两个公司相同数字用户也在各自目录保持独立业务；共享身份模型只在单公司内部使用，未来模块可复用身份但必须独立业务表。

backup.cmd包含数据库及独立进度库；本地配置备份含秘密，不能分享。恢复前stop.cmd，核实目标目录及完整性，运行restore.cmd 备份文件。已有新反馈时不能直接用旧库覆盖：先备份现库，采用兼容代码修复。累计迁移是增表、可重复，不改旧记录；回退程序也必须保留锁定规则，不能运行会允许撤销的旧版本。

Excel被占用时保留待更新状态，关闭后自动补写；管理员导出等待当前版本。中转故障保留幂等结果、发件与待刷新任务；重启恢复，旧消息不删除。电脑关机/休眠后本地业务服务停止，HTTPS空页面仍可访问但会显示后台离线；长期在线需要公司自己维护设备/托管，不能保证无人值守永不断线。

正式运营仅在用户最终验收并明确指令后执行：停机备份、现有cutover脚本只迁身份配置、不迁试用业务、核实正式空库及权限，再单实例启动。正式调度仍需单独确认工作日及授权，进度查询继续主动。
