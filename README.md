# Telegram 团队机器人｜Windows 快速独立部署

## 第一次安装

无需 Codex 或 ChatGPT。每家公司使用自己的 Telegram 机器人、工作群、Cloudflare 账户、密钥和本地数据库；不使用其他公司的私有备份初始化。

1. 准备自己的 BotFather 机器人及 Token、所有者数字 user_id、启用话题的工作群，以及“每日报表”“工作进度”两个实际话题 ID。机器人加入该群，关闭群隐私模式，并给予邀请用户、置顶所需管理员权限。
2. 下载并解压 [完整源码 ZIP](https://github.com/phallysonb-alt/telegram-team-bot/archive/refs/heads/main.zip)，双击 **setup-company.cmd**。选择与下载目录分离的运行目录（默认当前用户 LocalAppData 下的 TelegramTeamBot/company）。
3. 安装器检查 Python 3.12+、Node.js 22+；缺少时提供官方安装或 winget 选项。自动安装锁定依赖，生成独立配置、随机桥接密钥并初始化空白数据库。只输入五项 Telegram 必需信息，不自动登记示例员工。
4. 使用自己的 Cloudflare 账户完成浏览器授权；只有一个账户时自动选择，多个时选择本公司账户。安装器创建本次安装专属 Worker、D1、固定 workers.dev HTTPS 地址，部署前端及桥接。不会更改原有公司的 Sites。
5. 按提示在 BotFather `/newapp` 绑定这个 HTTPS 地址并填入短名；同意后可发送两条路由验收消息。检查通过后输入 `START` 才会启动本公司的唯一验收实例，可选择安装 Windows 登录自启动。
6. 员工先加入本公司的工作群、私聊机器人“开始”。在工作进度话题按原中文入口发布/查询任务，确认 Mini App 真实打开和保存；日报按下文原流程验收。**默认验收模式，正式调度关闭，不自动切换正式运营。**

再次双击下载目录的同一安装入口、指定同一运行目录，或在已安装运行目录双击入口，可继续中断的安装；不覆盖已存在的配置和业务数据。不同源码版本不是自动升级包，会拒绝覆盖。详细准备、恢复及人工授权见 [新公司快速安装](docs/新公司快速安装.md)。

跳过话题验证会明确保留“配置已保存、话题待验证”，返回待完成状态，不提示启动。再次运行只补未成功的话题；依赖指纹、锁定版本及健康检查通过时跳过重复安装。配置完成不等于部署成功，真实权限/话题检查不能跳过。

运行目录内：`start.cmd` 启动、`stop.cmd` 停止并暂停守护；`autostart-install.cmd` 设置当前用户登录自启动；**check-company.cmd** 统一检查配置、Telegram、HTTPS、D1、桥接和实例。诊断不提交员工业务，不取 Telegram 更新，不调用 bootstrap。离线安装可用 `setup-company.cmd -Offline`，仍需联网安装依赖；真正离线运行需预先准备依赖镜像。

电脑关机、休眠或用户未登录时，本地业务服务不可用；云端页面能打开不代表本地后台在线。同一 Token 不得在其他电脑同时 polling，安装器不能自动证明另一台电脑已经停止。验收边界见 [安装验证记录](docs/快速安装验证记录.md)。

## 功能与维护

供各团队独立部署的 Windows Telegram 机器人与工作进度 Mini App。包含日报、阶段任务、人员管理、审计、备份和两套独立 Excel 导出。各家公司自行管理机器人、HTTPS 服务、员工群、凭据和数据库；程序不提供公共业务数据服务。

本项目采用 [MIT许可证](LICENSE)，允许下载、修改和独立部署。第三方依赖保留各自许可证，详见 [许可证与依赖说明](docs/许可证建议.md)。各公司的密钥、身份库与业务历史不属于公开分发内容。

下载：[源码ZIP](https://github.com/phallysonb-alt/telegram-team-bot/archive/refs/heads/main.zip)；或运行 `git clone https://github.com/phallysonb-alt/telegram-team-bot.git`。安装前阅读下方运行环境和独立部署说明。

GitHub版本维护已接入：后续Codex修改、通过相关测试后，使用 `sync-github.cmd sync --message "修改说明"` 自动提交并推送已授权仓库。新电脑克隆后先运行 `sync-github.cmd install-hooks`。保密、离线补推和冲突规则见 [GitHub托管与自动同步](docs/GitHub托管与自动同步.md)。

可选的桌面两份历史 Excel 自动同步已接入。目录按本公司配置，默认关闭，保留原始导出文件及格式；占用重试与重启补齐见 [桌面历史表自动同步](docs/桌面历史表自动同步.md)。

管理员总表现分别显示本轮反馈与截至所选轮次的累计任务进度。未反馈不会隐藏历史完成阶段；查看历史不引入后续完成阶段。用法及回退见 [跨轮累计总表修复](docs/跨轮累计总表修复.md)。

总表进一步用实心灰、蓝、浅灰区分历史完成、本轮新增和未完成；按所选任务/轮次连续展示历史及本轮问题。问题分页、完整原文及旧记录不确定性说明见 [三色进度与历史问题](docs/三色进度与历史问题.md)。

稳定性第一阶段包含403/503分类、成员核验临时故障安全重试、桥接心跳节流和脱敏诊断。安装及Git更新不会自动更新其他公司的运行实例或Sites部署。参数、性能边界及发布预案见 [版本验证记录](docs/版本验证记录.md)。

继续使用现有数字身份、数据库、审计与备份。日报冻结；工作进度独立保存。管理群静默，培训暂缓，不调用 Gemini。验收与正式业务数据库分开，不转换模拟记录。

## 安装与运行
需要 Python 3.12+；部署 Mini App 云端及执行前端测试需要 Node.js 22+。运行 install.cmd 安装锁定依赖及本地测试；复制 .env.example 为 .env，用 configure.cmd 配置自己的机器人、所有者、群与两个实际话题 ID。密钥只留本地。运行 start.cmd，stop.cmd 停止已核实的进程树。diagnose.cmd 为本地诊断；backup.cmd 创建私密备份。

新部署顺序：安装运行环境 → 安装依赖和测试 → 配置本公司 `.env` → 初始化本公司空库 → 配置自己的固定 HTTPS/Mini App → 验收权限及路由 → 单实例启动。完整命令及恢复步骤见 [独立部署](docs/独立公司部署与恢复.md)。不要拿他人公司的私有备份作为初始数据；不要把示例模板中的模拟员工导入业务库。

仓库不分发 Python/Node 运行环境或可选专有制表库。未安装可选 `@oai/artifact-tool` 时，使用项目已有 openpyxl 兼容路径；无需登录 ChatGPT 或使用 Codex 才能运行。部署依赖使用 `deploy/package-lock.json` 与 `npm ci`，不在服务器上任意升级版本。

每个项目目录使用一个 polling 实例；实例锁阻止重复启动。不要另开 getUpdates。Windows 登录自启用 autostart-install.cmd，取消用 autostart-uninstall.cmd。stop.cmd 会留下人工停止标记，避免守护程序重新启动。后台网络中断自动重连；电脑关机或休眠时本地服务停止，云端页面会显示离线，业务不能保存。

登录自启使用 pythonw 无控制台入口；守护脚本、启动辅助程序和后台解释器均避免创建额外终端。已有 python.exe 机器人仍能正确识别，不因更新脚本而重复启动。详见[Windows 启动与恢复](docs/独立公司部署与恢复.md#windows-无控制台启动)。

启动/停止共用本公司生命周期锁，PID同时记录内核创建时间。`stop.cmd` 先请求 PTB 正常退出，默认等待60秒，超时保留PID和暂停标记，不自动强杀。可先用 `stop.cmd -TimeoutSeconds 180` 延长等待；明确需要强制停止时才使用 `stop.cmd -Force -TimeoutSeconds 0`，且仅处理核实过身份的本项目进程树。强停可能中断处理中请求，不能承诺任意故障下外部消息恰好发送一次。旧运行实例没有新停止监听，需要另行授权受控更新，本轮源码提交不会主动重启它。复现、回归及上线边界见[第三阶段关键修复](docs/第三阶段关键修复.md)。

默认 RUN_MODE=trial、SCHEDULE_ENABLED=false、AI_ENABLED=false。正式调度需要另行授权；当前工作日配置仍待确认，不能自行启用。验收记录不会自动转成正式业务。

## 人员与工作进度
工作群的有效普通成员通过实时数字身份核验自动登记，日报和进度共用一份人员状态。群主、群管理员、机器人及纯管理角色不自动算业务员。群管理员不会自动获得业务管理员权限。退出后停用，再入群按相同数字身份恢复；人工停用不能被自动登记解除。成员事件失败持久重试，首次业务访问补核验。

Mini App 仅保留发布、本人反馈和总表。管理员发布三或四阶段的顺序／自由任务，＋任务批量追加，成功后草稿清空。在进度话题发送“查询任务”发起当日全部有效任务的新查询，持久“填写进度”入口始终可重开。总表查看各任务、人员、具体阶段、当前问题及查询历史。

已提交阶段累计锁定，同轮已提交页面只读。新轮沿用相同任务的已完成阶段，本轮仍须本人再次提交；新问题默认留空，原文独立归档。首次未完成任何阶段也可提交0项，与未反馈区分。保存失败保留页面输入及幂等键，重试不重复写入。已有反馈的任务不能改写阶段结构；另发布独立任务避免解释旧勾选。旧工作台数据保留，旧按钮停用。

详细流程见 [员工说明](docs/员工说明.md)、[管理员说明](docs/管理员说明.md)。

## 冻结日报
发送完整日期、新增、维聊、有效、精聊及可选多行备注即提交。保存成功优先在原消息👍，失败仅回“已记录”。没有预览和确认按钮。数字非负整数，0有效，空白不为零；备注不参与指标。按填写的业务日期补交，同日完整重发替换，完全相同内容去重，历史与审计保留。

中文“日报模板 [日期]”“查看日报 [日期] [页码]”，管理员私聊“导出日报表”。每次主动查询在底部回复最新汇总；补交及修订只编辑该日最新查询表，无查询时不自动弹表。表格姓名与 Telegram 用户名分列，空用户名显示—；完整备注及最近7个已结束自然日统计保留。身份始终为数字 user_id。

Asia/Shanghai：23:00含至次日00:00不含为正常窗口，00:05汇总前一天。窗口外按原日期提前、补交及修订，工作日未确认，正式调度关闭。应交按既有生效、在职、日报要求及请假规则；历史未知人数不按今天名单推算。

exports/日报历史记录.xlsx 继续两个工作表，日期为真实业务日期且显示 yyyy-mm-dd，明细每日独立合并日期条，名称/用户名/备注左对齐，指标居中，备注换行。数据库单向生成，文件占用保持旧有效文件并后台重试，导出先确保当前版本。

## 独立进度历史
exports/工作进度历史.xlsx：查询汇总、员工进度历史、当前问题历史、任务定义四张表。按用户确认的 V2 模板分任务、保留完整网格及历史。日期是真实 Excel 日期，内容居中换行，每条反馈独立一行，问题原文完整存于所属单元格，不拆空白续行；极端长度另做隔离验证。查询名单、任务版本、实际反馈时间、阶段累计及新增值分别记录。旧可修改时代缺乏依据的增量留未知，不伪造完成事件。

导出与自动刷新共用数据库版本。文件占用或写入失败保留旧有效文件及待更新，启动补齐。现有电脑继续使用原 artifact-tool 生成器；另一公司无该工具时使用锁定 openpyxl 的兼容生成器，无需 Codex。两者均保留独立数据文件，进度不写日报 Excel。

## 测试与定位
test.cmd 或 python -m team_bot test 运行去重后的当前门禁；旧数量打卡、人员 Mini App 审批及旧确认界面测试保留源码并明确跳过，不计通过。原始全库历史审计曾发现35项旧预期不符，已更新现行锁定/导出预期，停用界面另有拒绝旧入口测试。自动测试不等于真实客户端验收。

核心：member_registry.py/onboarding.py（统一数字身份与重试）；progress_rounds.py/progress_lock.py（轮次、累计锁定、增量、迁移）；progress_miniapp.py（签名、权限、保存、幂等）；miniapp/app.js（表单与展示）；miniapp_fast_bridge.py/deploy/worker.js（持久中转、恢复）；progress_messages.py（转义 HTML 群消息）；progress_history_v2.py/progress_export.py（历史投影与安全更新）。daily.py/daily_history.py/daily_names.py/scheduler.py 业务源码保持冻结。

独立部署见 [部署与恢复](docs/独立公司部署与恢复.md)，代码托管验证见 [版本验证记录](docs/版本验证记录.md)。公司实际联调记录保留本地，不上传。仓库不含密钥、实值配置、业务库、日志、真实培训内容或运行环境。

## 安全维护

漏洞和泄露报告方式见 [安全政策](SECURITY.md)。每次提交扫描暂存文件，每次推送复核新增提交及提交信息；模板按审核过的 SHA256 放行。新电脑必须安装仓库钩子。对所有本地 Git 对象进行只读检查：

```powershell
python scripts/publication_audit.py --output ../private-audit/git-history.json
```

发现历史风险时保留私有状态。删除工作区文件、加入 `.gitignore` 或新增安全提交都不会移除旧历史。GitHub 发布附件、Actions 日志/工件及平台缓存需要另行核查。审计报告及完整 Git 备份保存在仓库外，不作为公开 Release 附件。
